Пользовательский опыт в RatioT SCADA

Эта страница — выжимка из «Руководства по эксплуатации» (≈2800 стр.) именно про то, как конечный пользователь работает с Web UI.

Фокус: что это за система, для чего она нужна, как в неё зайти, как перемещаться и выполнять рабочие задачи.

Что такое RatioT SCADA и зачем она нужна

RatioT SCADA — это программная платформа для диспетчеризации, мониторинга и управления промышленными объектами, инженерными системами и оборудованием.

Для чего используется

Сбор данных

Подключает PLC, RTU, датчики, счётчики, IoT-устройства по десяткам промышленных протоколов и считывает текущие значения.

Визуализация

Показывает состояние объектов на мнемосхемах, дашбордах, трендах, таблицах и SVG-схемах в реальном времени.

Управление

Позволяет оператору подавать команды на оборудование: включить/выключить, изменить уставку, запустить тест, квитировать аварию.

Аварии и события

Фиксирует отклонения, формирует аварийные сообщения, журналы, отправляет уведомления (e-mail/SMS) и контролирует SLA.

История и отчёты

Хранит временные ряды, события и архивы. Позволяет строить отчёты и аналитику через SQL, R, Python или встроенные инструменты.

Разделение доступа

Каждый пользователь видит только свои объекты и дашборды. Поддерживаются роли, группы устройств, интеграция с LDAP/AD.

Кто работает с системой

  • Операторы / диспетчеры — смотрят текущее состояние, реагируют на аварии, управляют оборудованием.
  • Инженеры / наладчики — настраивают устройства, создают дашборды, пишут скрипты.
  • Администраторы — управляют пользователями, лицензиями, сервером, резервным копированием.
  • Руководство / аналитики — используют отчёты и исторические данные для принятия решений.

Где работает пользователь

Основной интерфейс — Web UI, который открывается в браузере. Не требуется устанавливать клиентское приложение.

Администраторы дополнительно используют Net Admin (порт 6440) для лицензирования и серверной настройки.

Как и куда заходить

Быстрый старт: открой в Chrome/Firefox адрес https://<IP_сервера>:8443/web, введи admin / admin и нажми Login. После входа откроется Default Dashboard.
  • Открывать только в Google Chrome или Mozilla Firefox.
  • URL по умолчанию: https://<host>:8443/web или http://<host>:8080/web.
  • Если настроен сертификат с ошибкой, браузер предупредит — нужно принять риск/исключение.
  • Учётка по умолчанию: admin / admin.
  • Стартовая страница — Default Dashboard. Она же открывается по кнопке Home.

URL-адреса внутри Web UI

ПутьНазначение
/webГлавная страница (Default Dashboard)

Главное меню и навигация

В шапке Web UI обычно три пункта:

  • RatioT SCADA — логотип/название, часто ведёт на домашний дашборд.
  • Home — возврат на Default Dashboard.
  • Logout — выход из системы.

Дальше пользователь перемещается по дашбордам: через ссылки внутри мнемосхем, кнопки, таблицы, динамические панели.

Переходы между дашбордами

Из binding или скрипта можно открыть другой дашборд:

{web/redirect("users.admin.dashboards.example")}

Параметры перехода:

  • historyUrlChanged = false — URL не меняется.
  • newTab = false — открыть в текущей вкладке.
  • parameters — передать данные в целевой дашборд.

Дашборды

Каждый дашборд — это объект в контексте пользователя:

users.<username>.dashboards.<dashboard_name>

Типы дашбордов

Default Dashboard

Открывается после входа. Настраивается администратором как стартовая точка.

Landing Dashboard

«Посадочная» страница, на которую можно прийти по короткому URL. Например, /web/dashboards/users.admin.dashboards.landingDashboard или даже /landingDashboard, если настроен alias.

Административный дашборд

users.admin.dashboards.administration — для настройки сервера, пользователей, устройств.

Autorun — автозапуск

У пользователя может быть объект users.<username>.autorun. Он выполняется сразу после входа. Типичное применение — автоматически открыть нужный дашборд или выполнить действие.

Короткие ссылки и alias

Дашборд можно открыть по полному пути или по alias. Например:

http://example.com/web/dashboards/users.admin.dashboards.a

Или использовать {env/alias} внутри binding.

Компоненты интерфейса и binding

Все элементы управления (кнопки, поля, диаграммы, таблицы, SVG) живут внутри форм. Форма — это контейнер с компонентами.

Адресация компонентов

form/<component>:<property>

Примеры:

  • form/textField1:text — значение текстового поля.
  • form/image1:imageTable$imageData[0] — данные изображения.
  • form/gauge:datasets[1] — набор данных gauge.

Binding — связывание со значениями

Синтаксис:

{context:property}

Примеры:

{users.admin.devices.virtual:random}
{form/numberField1:value} * 100
round(10 * {users.admin.devices.virtual:random})

События компонентов

События обозначаются через @:

form/button1:click@
form/button1:mouseClicked@

Действия (Actions)

Действие над контекстом:

{cardholders:import!}

Через скрипт:

callFunction("", "executeQuery", {form/queryText:text})

Основные виджеты

  • Label / Text — текстовые надписи.
  • Button — кнопки с обработчиками.
  • Text Field / Number Field — ввод значений.
  • Data Table — таблицы с данными, фильтрами, сортировкой.
  • Line Chart / Gauge / Traffic Chart — диаграммы и индикаторы.
  • Image / SVG — встроенная графика и SVG-манипуляции.
  • Panel — контейнеры с динамическим содержимым.

Динамические панели

Панель может генерировать дочерние элементы из таблицы. Это позволяет рисовать списки, карточки, повторяющиеся блоки без ручного дублирования.

Пользователи и права доступа

Вся модель безопасности построена на иерархии контекстов:

users.<username>.devices.<device>
users.<username>.dashboards.<dashboard>
users.<username>.alerts.<alert>

Как работают права

  • Пользователь видит только те объекты, которые лежат в его ветке users.<username>.*.
  • Администратор users.admin видит практически всё, включая users.*.
  • Можно задать доступ через группы устройств: users.<username>.devgroups.<group>.
  • Доступ может быть ограничен на уровне отдельных свойств и действий.

Регистрация пользователей

В конфигурации сервера есть параметр usersSelfRegistration:

  • true — новые пользователи могут зарегистрироваться сами через Web UI.
  • false — только администратор создаёт пользователей.

Аварии и события

Система ведёт журнал событий и поддерживает активные аварии — ActiveAlerts.

Поля активной аварии

ПолеСмысл
locationГде произошла авария (контекст)
eventID события
alertТекст/имя аварии
typeТип
timeВремя возникновения
levelУровень критичности
messageСообщение для оператора

Уровни событий

В мануале встречаются уровни от 0 до 5 (чаще всего 0 — критичный, 5 — информационный). Конкретная расшифровка зависит от настройки проекта.

Квитирование

Аварии можно квитировать из таблицы или по нажатию кнопки. В binding/скрипте используется соответствующее действие над контекстом аварии.

Фильтры событий

Оператор может настроить фильтры, чтобы видеть только свои события, события по устройству или за период. Фильтры хранятся в контексте пользователя.

Типовые сценарии пользователя

1. Просмотр текущих значений

Открыть дашборд → посмотреть на label/gauge/chart, значения которых привязаны к тегам устройств.

2. Управление оборудованием

Нажать кнопку → вызвать action → устройство выполняет команду (например, buzz(), reboot(), selfTest()).

3. Подтверждение аварии

В таблице активных аварий нажать кнопку «Квитировать» или выполнить соответствующее действие.

4. Просмотр истории

Открыть Data Table с историческими данными, выбрать период, применить фильтр.

5. Переход к деталям

Клик по строке/кнопке → web/redirect() → открывается детализированный дашборд объекта.

6. Выполнение отчёта/запроса

Ввести параметры в поля → нажать кнопку → таблица обновляется результатом SQL-запроса или вызова функции.

Кастомизация интерфейса

  • Страница входа: шаблон loginPage.html лежит в <RatioT SCADA>\admin\web\static\templates. Поддерживает переменные {{loginUsername}}, {{loginPassword}}, {{loginSubmit}}, {{loginRegister}}, {{formError}}.
  • CSS: каждый компонент можно стилизовать через CSS, включая размеры, цвета, отступы, grid.
  • Адаптивность: поддерживаются breakpoints (Mobile, Tablet, Laptop, Full HD, QHD, Ultra HD) для разных разрешений.
  • Иконки: можно назначать компонентам и действиям через iconId.

Пример кастомного binding

// Цвет фона в зависимости от аварии
{.:voltageAlert$voltageAlert}
  ? "background-color: red"
  : "background-color: green"

// Переход на другой дашборд по клику
{web/redirect("users.admin.dashboards.detail", false, false)}
